# 风险最高的假设：识别、最小检查与结论

- 日期：2026-10-15 识别并检查；2026-10-16 整理为独立交付文档
- 检查脚本：`toy/check_riskiest_assumption.py`（纯标准库，Python 3）
- 复现：`cd recovery-baseline && python3 toy/check_riskiest_assumption.py`

## 1. 假设（风险最高的一个）

**A1：完整保存并恢复全部状态后，中断/恢复运行能与不间断运行在浮点位级等价。**

为什么它是风险最高的假设：

1. **它是整个价值主张的地基。** "可恢复训练"的全部意义在于"恢复 ≡ 未中断"。若 A1 不成立，"恢复"与"重跑"只剩速度差异，没有等价性可言——后续所有设计（要不要做全状态保存、允不允许部分恢复）都建立在这块地基上。
2. **它有最强的"显然成立"欺骗性。** 基线 `toy/recovery-baseline.py` 保存 checkpoint 且输出正确，看起来"恢复没问题"；但它只存了 `step` + `weight`。把"能跑"误认为"等价"是最典型、代价最高的错误。
3. **证伪成本不对称。** 若在投入大量实现（优化器状态、RNG 状态、框架对接）之后才发现等价假设有问题，返工代价远大于先花几分钟在 toy 层检验。

## 2. 最小但有效的检查

**检查设计**：在基线 toy 上，不间断跑 10 步 vs 跑 4 步 → 写入 `toy/checkpoint.json`（JSON 序列化往返）→ 读回 → 再跑 6 步，逐步对比最终状态（`==` 与 `repr` 两级，位级判定）。

"最小"与"有效"的取舍：

- **不能再小**：单次 4+6 分段已同时覆盖两个最致命的失效面——状态完整性（分段前后语义连续）与序列化往返（JSON 写读是否无损）。再小（如不经过文件、只在内存分段）就测不到序列化这一面。
- **不再更大**：此时还没有优化器状态和 RNG（那正是被怀疑缺失的东西），先在最便宜的层面上检验最致命的假设；更大规模的检查放在假设被初步确认之后（见 §5 的后续核验链）。

## 3. 实测结果（2026-10-15，负责人亲自运行并复核）

```
uninterrupted: step=10 weight=2.6778774528
resumed      : step=10 weight=2.6778774528
bit-exact equal: True
checkpoint keys saved: ['step', 'weight']
```

**结果：A1 通过——在位级判定下两者完全一致。** 多次重跑输出相同。

## 4. 结论与理由

**为什么通过是可信的**：该 toy 的更新是确定性单线程浮点运算，且 Python 的 `json` 序列化使用 `repr`，对 float 无损往返——分段恢复与不间断运行在数学上执行完全相同的浮点序列，位级一致是预期结果而非巧合。

**为什么不能外推（同等重要）**：该 toy 没有优化器状态、没有随机性。因此 A1 的通过范围被明确限定为"机制层"——它证明的是"状态保存与恢复的逻辑可以无损耗"，而不是"真实训练的恢复与未中断等价"。后者需要真实语义下的再检验。

**同一检查同时证伪了伴随假设 A2**："基线 checkpoint 足以支撑忠实恢复"——`checkpoint keys saved: ['step', 'weight']`，缺优化器与随机状态，**不成立**。这一证伪直接触发了工作计划中的 T2（全状态 checkpoint 实现），即：最小检查的产出不是一句"通过"，而是一个被重排的实现优先级。

## 5. 后续核验链（开放风险如何被关闭）

| 后续假设 | 关闭方式 | 结果 |
|---|---|---|
| A3：缺失/不兼容 checkpoint 可被静默容忍 | T3/selftest 负例测试（机制层 5 例 + 真实模型层 5 例） | **证伪**（好消息）：全部显式拒绝，exit=2、stderr 可读、无 Traceback、无静默继续 |

## 6. 一句话结论

A1 在受控 toy 层**成立**，作为"全状态保存值得做"的最小证据被接受；其保证范围被明确限制在机制层，真实模型层的等价主张由 T5 以容差级单独建立——假设检查的价值不在于"通过"，而在于它用最小成本划清了"已验证"与"未建立"的边界，并直接决定了后续工作的优先级。
